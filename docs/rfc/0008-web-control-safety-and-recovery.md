# RFC 0008：Web 控制的视频安全与维护恢复

- 状态：产品要求已确认；实现与验收分别记录。
- 日期：2026-09-16
- 范围：可信内网 Web 控制、单设备视频与手控、批量固件升级、设备维护。
- 不包含：公网、Wi-Fi/4G、多站点、200 台容量或未经验证的实体运动放行。
- 来源：本轮设计审查中用户逐项确认的八项决定。

## 1. 已确认的要求

| ID | 触发条件 | 必须满足的行为 |
| --- | --- | --- |
| WC-01 | 固件升级失败或更新过程中断电 | 在支持可恢复升级的设备布局上，恢复供电后自动恢复可用旧版本；不要求现场 USB 救援。恢复后保持停止，旧命令和租约失效。 |
| WC-02 | 新固件本地安全自检通过，但 Bridge 离线 | 保留新版本，主机升级任务等待连接确认；设备保持安全停止。不能仅因主机离线判定本地自检失败并回滚。 |
| WC-03 | 操作者看到的视频冻结、过期或无法证明新鲜 | 拒绝取得/续用方向控制，撤销现有手控租约；视频恢复不自动恢复运动。 |
| WC-04 | 浏览器控制连接或 Bridge 链路失效 | 取消运动目标，按设备安全策略停止并释放扭矩；不自动回正。重连后必须由用户主动恢复。 |
| WC-05 | 固件批量升级中一个目标失败或结果无法确认 | 暂停尚未开始的目标；已开始设备安全收尾或独立回滚；成功目标保留新版本。整批需要用户明确恢复。普通离散批量命令继续使用原有 best-effort 语义。 |
| WC-06 | 设备恢复出厂 | 只清除设备用户配置与配对；保留不可变硬件身份、硬安全常量和升级恢复信任。主机会话、长期记忆、审计不随设备重置删除。 |
| WC-07 | 最后一个观看页面关闭或断开 | 控制连接失效立即触发手控释放；采集在短暂、有界的宽限期后停止。自动停止后必须显式重新开启预览。 |
| WC-08 | 手控视频新鲜度判定 | 从实际采集到显示的画面年龄不得超过 500 ms。接收旧帧、重复帧或旧帧分片不得刷新有效期；年龄不可证明时拒绝手控。 |

## 2. 对现有决定的修订

本 RFC 中的已确认规则优先于旧文档中与之冲突的产品行为描述：

- “失联后回到安全姿态”明确为停止、取消目标、释放扭矩，不包含自动 home。
- 手控必须与当前设备、当前会话及操作者实际显示的有效视频绑定。取得手控时停止视频的
  旧互斥路径不满足本要求；不能为同时运行而削弱反馈、限位、卡滞或急停门禁。
- 本地启动自检与主机升级任务完成是两个独立事实。前者通过可以保留新固件，后者仍须
  核验设备身份、固件版本和健康状态，不能由 HTTP 接受或重启请求成功替代。
- 一台失败暂停后续目标的规则只适用于固件 rollout；不会把普通批量动作改成全体回滚。
- 恢复出厂和“删除主机记忆/会话”是独立操作，确认界面必须准确描述作用范围。

## 3. 协议与执行边界

设备 envelope 仍以 `contracts/phase1/envelope.schema.json` 为唯一事实源。新增 payload
必须有明确 capability、严格字段约束和会话失效规则；Web DTO 不能直接转发到设备。

画面年龄与手控输入 TTL 是不同指标。500 ms 的输入过期测试不能证明 500 ms 的画面年龄；
时间映射必须有可信的采集时刻和有界误差，不能把“主机刚收到一帧”当作“刚采集一帧”。
显示确认只能关联服务端已发送的当前帧，不能接受浏览器自报任意新鲜时间。

本地确认须绑定设备、会话、具体操作及不可变参数/镜像摘要，一次性使用。重连、过期、
取消或故障后失效。不得把浏览器提交的布尔值当作本地确认、签名验证或硬件兼容证据。

旧单应用分区设备不能承诺升级断电后的自动恢复；缺少回滚布局、可信签名验证或必要能力
时必须在写入前拒绝。分区布局迁移和信任配置属于独立部署步骤，不能由普通 Web 升级
偷偷改写 bootloader、分区表或 eFuse。本轮代码实现不授权设备刷写或实体运动。

## 4. 验收要求

每项实现记录必须关联 WC-01 至 WC-08，分别列出 host/fake、固件 host、目标构建、浏览器、
真实媒体与硬件 HIL 的结果。未测试项保留 NOT TESTED，不能由软件测试替代。

必须覆盖：

- 视频与手控同时运行时的画面年龄；延迟帧、重复帧、分片滞留、时钟不确定、旧 session、
  页面不再呈现新帧、服务端持续收帧但客户端不更新，以及视频恢复后不自动续控。
- 最后观看者离开、多个观看者之一离开、宽限期内重连、宽限期结束后显式重新开启。
- 浏览器/Bridge 失联、重连和重启后不回正、不恢复旧命令/租约。
- 升级传输中断、镜像校验失败、首次启动失败、本地自检通过但 Bridge 离线、回滚后保持
  停止，以及所有写入边界的断电恢复；真实断电验证属于独立硬件验收。
- 批次失败/结果不明后的暂停、明确恢复、已成功目标保留、已开始目标收尾及主机重启恢复。
- 恢复出厂确认失效/重复使用/操作不匹配，以及设备重置不会删除主机记忆、会话或审计。

所有生产运动能力仍须满足独立实机门禁；本 RFC 不取消 RFC 0002 的受监督 HIL 要求。
